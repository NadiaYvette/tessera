# Tessera — SSG-4 IOMMU / DMA track (proof plan)

`doc/system-state-goals.md` §SSG-4 is now fully sourced on all three platforms
(PCIe 6.0 ATS/PRI + Intel VT-d 5.20 + Arm SMMUv3 H.a + AMD-Vi 3.11). This file
is the **scoping/proof plan**: what the track proves, how it reuses the Stage 1/2
machinery, and where it must go beyond a straight replay.

## The property

> **`IOTLB ⊆ mapping`** — every cached device translation agrees with the current
> CPU page table, so DMA cannot reach a freed or remapped frame.

Maintained by an **IOMMU shootdown on every unmap**, exactly as the CPU-TLB
coherence invariant (`Core.tlb ⊆ mapping`) is maintained by `sfence_vma_*` /
`deliver_ipi`. This is the CPU-TLB problem *replayed at a second translation
point*, plus one genuinely new thing: the translation is keyed by the **device**
(StreamID/BDF + PASID + IOVA), not by (satp, VA), and it is filled by the
**device's own requests** (ATS), not by the CPU.

## Model extension (`machine.sail` → `hardware/rocq/machine.v`)

The IOMMU walks the *same* `Machine_mem` page table as the CPU (the clustered-VM
case is first-level-only: one GPA→SPA table shared with the CPU), but caches into
its own translation cache:

```
Record IotlbEntry := {             (* the ATS translation completion *)
  IotlbEntry_did   : Z;            (* device id: StreamID / BDF *)
  IotlbEntry_pasid : Z;            (* PASID, 0 for no SVM *)
  IotlbEntry_iova  : mword 64;     (* the device address being translated *)
  IotlbEntry_ppn   : bits 44;      (* the resulting physical page *)
  IotlbEntry_perm  : Perm;         (* Read / ReadWrite — devices never X *)
}.
```

`Machine` gains one field (`Machine_iotlb : list IotlbEntry`), generated by
editing `machine.sail` and re-running `build.sh` — the same one-line-extension
pattern that added `Machine_ram`/`Machine_ipi`.

- `iommu_walk (did pasid) (iova) (mem) : option (ppn × Perm)` — the second
  walker: the *same* `translate` body, but the input address is `iova` and the
  result is cached per (did, pasid). In the first increment it is literally
  `translate` with the `Core.satp_ppn` fixed to the domain root; PASID/SVM
  (two-level first/second-stage, `GPA→SPA` + `GVA→GPA`) is a later increment.
- `iommu_fill (did pasid) (iova) (mem) (iotlb) : list IotlbEntry` — ATS
  translation request → walk → completion (cache insert). Fills only on a
  **hit**; a fault is reported via PRI (below), not cached.
- `iotlb_invalidate (iotlb) (va) : list IotlbEntry` — the **queued-invalidation
  descriptor** (VT-d `IOTLB Invalidate` §6.5.2.3 / SMMU `TLBI` §4.4 /
  AMD-Vi `INVALIDATE_IOMMU_PAGES` §2.4.3): drop every entry whose `iova`
  falls in the unmapped page. This is the IOTLB twin of `sfence_vma_va`.

`IOTLB ⊆ mapping` is then the IOMMU twin of the CPU coherence predicate:

```
iotlb_coherent (mem) (iotlb) :=
  ∀ e ∈ iotlb, iommu_walk e.did e.pasid e.iova mem = Some (e.ppn, e.perm).
```

## Stage 4.1 — the functional replay (single device, SC)

Replays **Stage 1/1.1** (`coherence.v` / `coherence_leaf.v`) at the IOTLB:

- `iommu_unmap_correct` — `unmap (iotlb_invalidate m va) va` re-establishes
  `iotlb_coherent` (the IOMMU twin of `unmap_correct`).
- `iommu_unmap_without_invalidate_breaks` — `unmap m va` *without*
  `iotlb_invalidate` leaves a stale IOTLB entry, so a DMA read of the freed
  frame succeeds — the direct analogue of `unmap_without_flush_breaks_coherence`,
  and the exact bug class the ATS/queued-invalidation machinery exists to prevent.
- Leaf-entry removal generalisation (`coherence_leaf.v`) carries over: the
  invalidate must drop *leaf* entries covering `va`, not just the root walk.

**What is genuinely new here (not a replay):** the walker is keyed by `(did,
pasid, iova)` and filled by ATS, so the "coherence" statement quantifies over
*device translation points* rather than *cores*. That is a one-parameter
generalisation of the existing `Core.tlb` predicate, not new proof structure.

## Stage 4.2 — the concurrent IOTLB shootdown

Replays **Stage 2** (`shootdown.v` → `shootdown_iris.v` →
`shootdown_weak_broadcast*.v`) with one new ordering obligation:

- `iommu_shootdown_correct` — the leader unmaps, then issues the queued
  invalidation (IOTLB Invalidate + **Invalidation-Wait** §6.5.2.9), and the
  *completion* of Invalidation-Wait means every prior IOTLB entry is gone —
  the IOMMU twin of the IPI-broadcast + ack-wait.
- **ATS device-TLB invalidations** (§4.3 / SMMU §4.5 / AMD-Vi §2.11) — the IOMMU
  must also shoot down the *endpoint*'s device-TLB, because the device caches
  translations locally. This is a **second broadcast tier**: IOMMU → each
  attached endpoint's device-TLB, with the ATS invalidation completion as its
  ack. The N-core shootdown machinery (leader → remotes → acks) instantiates
  once for the IOMMU's own IOTLB and once for the device-TLBs.
- **Weak memory** (S2.2/S2.5): the queued-invalidation *descriptor write* and the
  data it announces must be ordered the same way the PTE-write → pending release
  → doorbell chain is in S2.5 — this is the *same* gpfsl structure, with the
  interrupt controller (`intc.sail`) replaced by the IOMMU's command queue
  (`SMMU_CMDQ_*` §6.3.26-6.3.28 / AMD-Vi command buffer §2.4).

### S4.2b — the concurrent queued-invalidation shootdown (detailed increments)

S4.2a proved the **functional** IOMMU broadcast. S4.2b lifts it to genuine
concurrency under weak memory, replaying S2.2c/S2.5 with the interrupt
controller's per-hart mailbox replaced by the IOMMU's command queue. In three
increments, each landed build-green and axiom-free:

- **S4.2b-1 — the command queue (functional).** *(landed)* Add `Machine_ioqueue : list
  InvalidationCmd` (descriptors `IotlbInvalidate va` / `InvalidationWait`) and
  the functional `iommu_process_queue` that drains the queue (applying each
  invalidate to the IOTLB) and returns the Invalidation-Wait completion once the
  wait descriptor is reached. Prove `iommu_shootdown_via_queue_correct`: unmap →
  enqueue Invalidate + Wait → drain ⇒ every cached translation for `va` is gone
  (the queue formulation of S4.2a's `iommu_shootdown_correct`).
- **S4.2b-2 — the weak-memory lift (gpfsl).** *(groundwork landed; Iris lift
  pending)* The leader's PTE write (release) → command-queue descriptor write
  (release) → doorbell; the IOMMU's queue read (acquire) → drain →
  Invalidation-Wait completion (release) → the leader's completion read
  (acquire). This is S2.5's `pending → doorbell → ack` chain with the device
  (`intc.sail`) replaced by the command queue, so `bc_wait_all_intc_spec` /
  `bc_broadcast_intc_spec` re-instantiate with the queue as the ghost device.
  Prove the IRIS spec `iommu_broadcast_weak_spec`: the leader's unmap is observed
  by every IOTLB flush before the wait returns. The pure precondition is landed:
  `iommu_shootdown_via_queue_refines_iommu_shootdown` (S4.2b-1's queue drain and
  S4.2a's broadcast agree on mem + IOTLB); the gpfsl program is the next
  increment.
- **S4.2b-3 — the ATS device-TLB tier (a second broadcast).** *(landed)* The IOMMU's own
  IOTLB is one translation point; each endpoint's **device-TLB** (filled by ATS)
  is a second. The shootdown must invalidate both — `iotlb_invalidate` (IOMMU) and
  `ats_invalidate` (per-device; PCIe ATS §4.3 / SMMU §4.5 / AMD-Vi §2.11). This is
  the N-core broadcast instantiated twice (once over cores for the CPU-TLB, once
  over devices for the device-TLB), with the ATS invalidation completion as the
  per-device ack. Prove `iommu_shootdown_ats_correct`: after the full shootdown no
  CPU TLB, no IOTLB, and no device-TLB entry translates the freed frame.

The model additions 2b-1/2b-3 (`InvalidationCmd`, `Machine_ioqueue`,
`ats_invalidate`) are now in place (2b-1's command queue and 2b-3's ATS tier
both landed); 2b-3's `iommu_shootdown_ats_correct` makes the device-TLB tier a
proof obligation rather than just a field.

## Stage 4.3 — the device side (ATS / PRI), genuinely new

Not a replay. The device↔IOMMU interface (PCIe 6.0) introduces two flows the CPU
track never had:

1. **ATS translation request → completion.** The device asks the IOMMU for a
   translation, the IOMMU walks + caches, the completion fills the device-TLB.
   Proved: the completion's (ppn, perm) is exactly the walk's — `iommu_fill`
   inserts nothing the walk did not produce.
2. **PRI page-request.** On a fault, the device issues a page request, the kernel
   maps the page, and the device retries. Proved: a page request is serviced
   *at most once per fault*, and no DMA proceeds until the mapping exists — the
   "DMA cannot reach a freed frame" direction, now from the device's side.

These are the pieces that keep the IOMMU from being a copy of the CPU MMU: the
*client* of the translation cache is untrusted-ish (a device, not the kernel's
own hart), and it *pulls* translations (ATS) and *pulls* mappings (PRI) instead
of being pushed invalidations.

## Concrete increments (landed one at a time, build green each)

1. **S4.1a — model.** *(landed)* `Machine_iotlb` + `IotlbEntry` + `iommu_walk` +
   `iotlb_invalidate` in `machine.sail`, conformance vectors per platform.
2. **S4.1b — coherence.** *(landed)* `iommu_unmap_correct` /
   `iommu_unmap_without_invalidate_breaks` (+ leaf variant).
3. **S4.1c/d — universal invariant.** *(landed)* `pte_address` injectivity +
   `iommu_unmap_preserves_coherence` (the literal `IOTLB ⊆ mapping`).
4. **S4.2a — functional shootdown.** *(landed)* `iommu_shootdown_correct` over
   the pure `Machine` (the IOMMU twin of `ipi_broadcast_correct`).
5. **S4.2b-1 — command queue (functional).** *(landed)* `InvalidationCmd` +
   `Machine_ioqueue` + `iommu_process_queue` + `iommu_shootdown_via_queue_correct`.
6. **S4.2b-3 — ATS device-TLB tier.** *(landed)* `iommu_shootdown_ats_correct` +
   `find_devtlb` (lookup faults for the freed frame) — no CPU TLB, no IOTLB, and
   no device-TLB entry translates the freed frame.
7. **S4.2c — command-queue MMIO.** *(landed)* `cmdq_mmio.v` head/tail (prod/cons)
   registers; `cmdq_drain_refines_iommu_process_queue` (the MMIO drain realizes
   the functional queue; circular wrap is a later increment).
8. **S4.3 — ATS/PRI.** *(landed)* completion=walk, fault-caches-nothing,
   device-TLB tier, PRI dedup + PCIe 6.0 cross-check vectors.
9. **Conformance cross-check.** *(landed)* `iommu_conformance.v`: walker =
   translate re-rooted (`iommu_walk_translate_conforms`) + per-platform
   invalidation vectors (VT-d §6.5.2.3 / SMMU §4.4 / AMD-Vi §2.4.3).

10. **S4.2b-2 — the weak-memory lift (gpfsl).** *(landed)* The Iris
    program with the command queue (`cmdq_mmio.v`)
    as the ghost device: leader PTE write (release) → `cmdq_enqueue` + doorbell
    (release); IOMMU `cmdq_drain` (acquire) → Invalidation-Wait completion
    (release); leader completion read (acquire). Re-instantiates S2.5's
    `pending → doorbell → ack` chain (the 2-party leader↔IOMMU protocol, the
    S2.2b pattern, not the N-core broadcast). Pure precondition landed:
    `iommu_shootdown_via_queue_refines_iommu_shootdown` +
    `cmdq_drain_refines_iommu_process_queue`.
    **Landed (all three directions, axiom-free):** `iommu_broadcast_weak.v` proves
    (1) `iommu_broadcast_gen_inv` — the leader → IOMMU doorbell direction, a
    re-instantiation of `shootdown_weak_gen_inv` (S2.2a) with the request flag
    `1` as the message; (2) `iommu_broadcast_ack_gen_inv` — the IOMMU → leader
    completion direction (the S2.2b release/acquire ack); and (3)
    `iommu_broadcast_full_gen_inv` — the **composition**: four cells
    (`door`/`req`/`done`/`res`) and two `iq_inv`s, chaining the two release/acquire
    pairs so the leader provably reads the drained result `1` after the IOMMU
    releases the Invalidation-Wait completion.
    The abstract weak-memory core is complete and axiom-free: the three
    checked lemmas are `iommu_broadcast_gen_inv` (leader → IOMMU),
    `iommu_broadcast_ack_gen_inv` (IOMMU → leader), and
    `iommu_broadcast_full_gen_inv` (their composition).  The pure machine bridge
    is separately checked in `iommu_broadcast_reify.v` via
    `iommu_shootdown_via_queue_correct`.

    The machine-ghost integration is **landed**: the composition is stated
    generically (`iommu_broadcast_full_gen_inv_update`, threading `R ⊢ |==> R'`),
    and `iommu_broadcast_full_gen_inv_machine` instantiates it with the
    exclusive `machine_ctx` — the ghost update runs at the leader's final
    program step (inside the WP, before the atomic read), exactly as the
    atomic-step boundary requires, yielding
    `machine_ctx γm (iommu_shootdown_via_queue m root va p)` at the end.
    Both corollaries (pure and machine) are axiom-free and in the build.

    - *Ghost state:* reuse `shootdown_weak.v`'s `uniqTokΣ` (excl unitO) for the
      leader's exclusive write token.  Two heap cells: `iq_prod` (the doorbell,
      release-written by the leader after the PTE write) and `iq_iotlb` (the
      completion/result cell, release-written by the IOMMU after the drain).
    - *Program* `iommu_broadcast_weak : expr` (two threads):
      `leader: iq_iotlb <- #(encode invalid);; iq_prod <-ʳᵉˡ #1` (release the
      unmap + doorbell); `iommu: repeat: !ᵃᶜ(iq_prod);; iq_iotlb <-ʳᵉˡ #(encode drained)`
      (acquire the doorbell, release the drain completion); `leader:
      repeat: !ᵃᶜ(iq_iotlb)` (acquire the completion, observe the invalidated
      IOTLB).  The `encode`/`decode` pack the IOTLB state into a Z exactly as
      `encode_tlb`/`encode_pte` do for the TLB.
    - *Invariant* `iq_inv N` is `sd_inv` re-keyed: `iq_prod sw↦ ζ` with ζ the
      `0 → 1` history, and the `iq_iotlb` cell holding *either* the leader's
      token (not yet drained) *or* the drained value under the released view.
    - *Specs:* `leader_enqueue_spec` (release PTE+doorbell makes the invalidate
      observable), `iommu_drain_spec` (acquire doorbell + release completion
      realises `iotlb_invalidate`), `leader_wait_spec` (acquire completion
      observes the drained IOTLB), `broadcast_spec` (compose the three ⇒
      `iommu_shootdown_via_queue_correct` under weak memory).  Each closed under
      the global context (`Print Assumptions`), as S2.5's are.

11. **S4.4 — second-platform port.** *(most slices landed)*
    - ALL-granularity invalidation (`iotlb_invalidate_all` / `ats_invalidate_all`,
      AMD-Vi §2.4.8 / SMMU TLBI_ALL) — landed.
    - SMMUv3 two-stage walk (`smmu_walk`: GVA → GPA → SPA, `smmu_proofs.v`) — landed.
    - AMD-Vi 4-level walk (`amdvi_walk` = vpn3 then translate re-rooted,

    - Coherence replay of both walkers (unmap → invalidation → walk faults) —
      landed: `smmu_unmap_stage1_faults` / `smmu_unmap_stage2_faults` and

    - SMMU STE/CD tables are threaded through `Machine` and the end-to-end

    - **S4.5 VT-d first slice** — landed in `vtd_proofs.v`: Requester-ID-indexed

## What is replayed vs. new

| Piece | Replay of | New? |
|---|---|---|
| second walker (`iommu_walk`) | `translate` (Stage 1) | no — re-keyed to (did, pasid, iova) |
| coherence invariant (`iotlb_coherent`) | `Core.tlb ⊆ mapping` | no — parameterised over translation points |
| IOTLB invalidation (`iotlb_invalidate`) | `sfence_vma_va` | no |
| unmap-correct / without-invalidate-breaks | `unmap_correct` family | no |
| queued-invalidation shootdown + Invalidation-Wait | IPI broadcast + ack-wait | no |
| weak-memory ordering of the command queue | S2.2c/S2.5 | no (device changes, chain is the same) |
| ATS translation request/completion | — | **yes** (device pulls the cache fill) |
| ATS device-TLB invalidation (endpoint tier) | N-core broadcast | **yes** (a second, per-device tier) |
| PRI page-request servicing | — | **yes** (device pulls the mapping) |
| first/second-stage PASID/SVM translation | — | **yes** (deferred to a later increment) |

## Trust line

Identical to the CPU track (`doc/rigor-trust-line.md`): the IOMMU model is
hand-written Sail, **cross-checked** (conformance vectors, not a full refinement)
against VT-d/SMMU/AMD-Vi, and the proofs are machine-checked and axiom-free over
that model. The three specs are all current revisions (VT-d 5.20 April 2026,
SMMU H.a March 2026, AMD-Vi 3.11 April 2026). The same caveat as G1 applies: the
proofs are "correct conditional on this simplified IOMMU model being faithful",
closed only by a full derivation from the upstream Sail/formal models — of which
the conformance vectors are the first instalment.
